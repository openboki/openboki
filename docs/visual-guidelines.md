# 図解・イラスト・アニメーションの方針(v1)

更新日: 2026-11-19
状態: 採用(ADR 0004。2026-11-19にスポットイラストを自作のSVGに改定)。会計IDEの視覚表現をどの場面で、どの手法で作り、どう運用するかを定める。配色と記号は`docs/ide-design.md` 8章。

## 1. 原則

1. **視覚表現は説明に従属する。** 読み飛ばせる装飾は置かない。すべての図は「その図が無いと分かりにくいこと」を1つ持つ。
2. **会計の構造は「図解」で、物語の場面は「イラスト」で。** この2つを混ぜない。図解は正確さと一貫性、イラストは親しみやすさが役目。
3. **動くものが本体。** 会計IDEでは、学習者の操作に応じて財務諸表や帯が動くこと自体が最良の視覚表現。静止画の図解は、その動きの「説明書」として添える。
4. **1つの視覚言語。** 5要素の色と記号(ide-design.md 8章)、線の太さ、角丸、余白を図解・イラスト・UIで共通にする。素材を複数のソースから混ぜない。
5. **色に頼らない。** 記号・ラベル・形で区別し、altテキストを必ず書く。装飾は`aria-hidden`。
6. **ライセンスは台帳で管理する。** 外部素材(フォント、アイコン)は出所・ライセンス・使用箇所を記録する。イラストは自作し、外部のイラスト素材は持ち込まない。

## 2. 場面ごとの視覚表現

| 場面 | 何を見せたいか | 手法 | 例 |
|---|---|---|---|
| 財務諸表の動き(結果ペイン) | 記帳で何がどれだけ動いたか | データ駆動のUI(実装済み)+ 遷移アニメーション | 動いた行の強調、▲▼、「会社のかたち」の帯 |
| 取引の流れ | 仕訳の行が財務諸表のどこへ行くか | アニメーション(M1): 数字が該当行へ飛ぶ | 「現金80,000」が貸借対照表の現金へ |
| 会計の構造(5要素、貸借の左右、評価勘定) | 位置関係と包含関係 | 図解ブロック`elements` | 5つの箱に科目を置いた図 |
| 手続きの流れ(決算パイプライン、三分法の流れ) | 順序と段階 | 図解ブロック`flow` | 仕訳帳 → 総勘定元帳 → 試算表 → 財務諸表 |
| 期間と配分(減価償却、経過勘定) | 時間軸上の分け方 | 図解ブロック`timeline` | 1,200,000円を6年に分ける |
| 科目の増減(T勘定) | 左右の積み上がり | 図解ブロック`taccount`(M1でIDEのタブにも) | 現金のT勘定 |
| 方法の比較(直接法 / 間接法、定額法 / 定率法) | 同じ取引で何が違うか | 図解ブロック`compare`(2つの図を左右に) | 間接法では建物の金額が残る |
| 会社の形(比例縮尺) | 全体像と割合 | 図解ブロック`proportion`(M6で実データにも) | 資産vs負債 + 純資産 |
| 物語の場面(カフェ、コーヒーマシン、軽バン) | 親しみ、場面転換の合図 | スポットイラスト(小さく、ステップ見出しの横) | 開業日のカフェ |
| 概念のたとえ(費用配分 = ケーキを切り分ける) | 直感的な理解の足がかり | 図解ブロックで描けるものは図解で。描けないものはスポットイラスト | 6等分のケーキ |
| UIの記号 | 操作の手がかり | アイコン(Lucideのみ) | ✓、!、→ |
| 達成・区切り | 感情の起伏と達成感 | 入場・強調は控えめに。正解した瞬間と単元の最後のステップに着いた瞬間だけ画面全体の祝福を1回(両下からのクラッカーと上から降る紙吹雪、中央に「できました」と次へ進める旨の札。最後のステップは単元をやりきった旨の札。3秒以内、クリックは通す、セッション中の初回だけ、`prefers-reduced-motion`では出さない)。音は出さない | 「できました」のフェードイン、画面全体の紙吹雪と札、「次へ →」の1回のパルス |

## 3. 手法・ツールの比較

### 3.1 図解(構造・流れ・期間)

| 手法 | 長所 | 短所 | 判定 |
|---|---|---|---|
| **コードで描く(React + SVGの図解コンポーネント、コンテンツからはYAMLの`figure`ブロックで指定)** | 5要素の配色・記号と自動で一致。ダークモードやスマートフォン幅に追従。数値を渡せば比例縮尺も描ける。アニメーションに繋げられる。ライセンスの問題がない。AIエージェントがYAMLを書くだけで量産できる | 図の種類ごとにコンポーネントを作る初期コスト。自由な絵は描けない | **採用** |
| Excalidraw(手描き風の作図ツール、MIT) | 自由に描ける。手描き風は親しみやすい | 配色・線の統一が人手頼み。数値と連動しない。SVGを手で貼る運用になる | 図解ブロックで表せない図が出たときの補助。一次手段にしない |
| Mermaid / D2(テキストから作図) | テキストで管理できる | 見た目の制御が弱く、会計の図(左右の箱、比例)に向かない | 不採用 |
| 画像(PNG)で図を置く | 作るのは早い | 更新しにくく、文字が拡大でぼやけ、配色がずれる | 不採用 |

### 3.2 イラスト(物語の場面・たとえ)

| 素材 | ライセンス(2026-11-07時点、公式ページ確認) | 統一感・拡張性 | 判定 |
|---|---|---|---|
| **いらすとや** | 商用可。無料は「1つの制作物につき20点まで(重複は1点)」。「無料で閲覧できるオープンなサイト」でコンテンツが増え続ける場合は1記事20点まで。21点以上は1点1,100円(税込)目安。加工可だが「いらすとやと分からなくする加工」は不可。クレジット不要 | 誰もが知るスタイルで、サービスの印象が「いらすとや」になり、独自性と洗練から遠ざかる。無料公開の間は単元ごとに20点まで使えるが、将来サブスクリプションにすると「オープンなサイト」の条件を外れ、全体で20点の上限に戻る可能性が高い(規約に明文は無い) | **主要素材としては不採用**。ビジョン(独自の学び方)と料金方針(将来の有料化)の両方と相性が悪い |
| **自作のSVG(コードで描く)** | 権利が明確で、CC BY-SA 4.0で公開できる | 色をテーマのトークンで指定でき、4テーマ × ライト・ダークに追従する。描き方の決まり(6章)で絵柄を揃えられる。物の絵は実用になるが、人物や凝った場面は難しい | **採用(2026-11-19)** |
| unDraw | 商用可、帰属不要、点数制限なし。禁止は素材集としての再配布とAI学習への利用 | 人物中心の大きな構図で、見出し横の小さな枠では潰れる。色はSVGに焼き込まれ、テーマごとの加工が要る。日本の場面(軽バン、商工会議所)は無い。フォークされるリポジトリに同梱してよいか未確認 | 不採用(2026-11-19。当初は第一候補) |
| Loose Drawing | 商用/非商用・個人/法人とも無料。点数制限の記載なし。クレジット不要。加工可。再配布・販売は不可。無料はPNG(サイト上で色変更可)、SVGは有料 | 日本の作者による線画で、日本の場面に合う。人物中心。PNG運用になるので解像度と再着色に制約。再配布できない | 不採用 |
| Open Peeps / Open Doodles | CC0 | 人物の手描き風。物や場面の表現は少ない | 人物だけ必要なら候補 |
| Storyset(Freepik) | 無料は帰属表記が必要 | 点数も表現も豊富だが帰属表記がUIに残る | 不採用 |
| 画像生成AI(ラスター画像) | サービスごとに異なる。生成物の権利の扱いが不安定 | 枚数は無限だが、スタイルと細部(指、文字、会計の記号)の一貫性を保つ運用コストが高い。テーマの色に追従できない。学習用の正確さが要る図には向かない | 不採用(図解・学習用)。マーケティング用の1枚などに限って将来検討 |
| 委託(独自キャラクターとスタイルガイド) | 権利が明確 | 費用と時間。単元を足すたびに発注が要る | 人物やキャラクターが必要になったら検討。それまでは図解と物のスポットイラストで足りる構成にする |

### 3.3 アニメーション

| 手法 | 用途 | 判定 |
|---|---|---|
| **CSS transition / keyframes、tw-animate-css** | 入場・強調・幅の変化。`prefers-reduced-motion`で止める | **採用(実装済み)** |
| **`motion`(旧framer-motion、MIT)** | レイアウトの移動(数字が財務諸表の行へ飛ぶ)、共有要素の遷移 | M1の「取引の流れ」で導入 |
| ReactのView Transitions | ページ間の連続性 | 必要になってから |
| Lottie / Rive | 作り込んだキャラクターアニメーション | 不採用(制作ツールと運用が増える) |

ルール: 動かすのは状態が変わったときだけ。150〜500 ms。ループする装飾は置かない。動きには必ず静的な表現(▲▼、色、テキスト)が伴う。

## 4. 決定

1. **図解はコードで描く。** 図解ブロック(5章)を作り、コンテンツからはYAMLで指定する。種類は必要になった順に足す。
2. **イラストは自作のSVGで、1つの絵柄に統一する。** 物語の場面転換に使う小さなスポットイラストだけとし、6章の決まりでコードとして描く。外部のイラスト素材(unDraw、いらすとやなど)は使わない。
3. **画像生成AIの出力(ラスター画像)は学習コンテンツに使わない。** SVGは書き手が人でもAIエージェントでも、6章の決まりに合わせ、差分のレビューと画面での確認を通す。
4. **アニメーションはCSSを基本に、M1で`motion`を導入する。** Lottie / Riveは使わない。
5. **人物やキャラクターは、必要になってから検討する。** それまでの構成は、図解と物のスポットイラストだけで成立させる。

## 5. 図解ブロックの仕様(M1で実装)

説明文に```figureブロック(YAML)を置く。`type`ごとにzodで検査し、`src/components/figures/`のSVGコンポーネントが描く。すべて`ELEMENT_STYLE`の色と記号を使い、`alt`を必須にする。

```yaml
# 5要素の箱に科目を置く。leftに資産、rightに負債・純資産、下に収益・費用
type: elements
alt: 現金と備品は資産の箱に、借入金は負債の箱に入る
items:
  - { account: cash, highlight: true }
  - { account: equipment }
  - { account: loans_payable }
```

```yaml
# 流れ図。ノードは左から右(スマートフォンでは上から下)
type: flow
alt: 取引が起きると仕訳帳に書き、集計して財務諸表になる
nodes: [取引, 仕訳帳, 総勘定元帳, 試算表, 財務諸表]
highlight: 1
```

```yaml
# 期間と配分。合計をn期に分け、各期の額を示す
type: timeline
alt: 1,200,000円を6年に分けると、毎年200,000円
total: 1200000
periods: 6
unit: 年
# 任意。highlight: 先頭から強調する期の数(残りは薄く描く)。start_month: 1期目の月(期の名前が「4月」「5月」…になる)
```

```yaml
# T勘定
type: taccount
alt: 現金のT勘定。左に増加、右に減少
account: cash
debit: [{ label: 出資, amount: 1000000 }, { label: 売上, amount: 80000 }]
credit: [{ label: 備品の購入, amount: 600000 }]
```

```yaml
# 比例縮尺の貸借対照表(と損益計算書)
type: proportion
alt: 資産1,330,000のうち、負債が300,000、純資産が1,030,000
assets: [{ account: cash, amount: 730000 }, { account: equipment, amount: 600000 }]
liabilities: [{ account: loans_payable, amount: 300000 }]
equity: [{ account: capital_stock, amount: 1000000 }, { label: 当期純利益, amount: 30000 }]
```

```yaml
# 2つの図を左右に並べる
type: compare
alt: 直接法は建物を直接減らし、間接法は累計額で減らす
left: { title: 直接法, figure: { type: elements, items: [...] } }
right: { title: 間接法, figure: { type: elements, items: [...] } }
```

追加の候補(必要になったら): `journal-to-statements`(仕訳の各行が財務諸表のどこへ行くかを矢印で示す静止版)、`cycle`(会計期間の循環)。

## 6. スポットイラストの仕様

ステップの`## 見出し`の直後に```illustrationブロックを置き、名前を1つ書く。ガイドの見出しの右に76pxで出る。名前の一覧は`src/lib/illustrations.ts`、絵は`src/components/illustrations/spot-illustration.tsx`にあり、一覧に無い名前はビルドで落ちる。

````markdown
## コーヒーマシンを買う
```illustration
coffee-machine
```
````

描き方の決まり。新しい絵はこれに合わせ、既存の絵と並べて画面で確かめる。

- 枠は`viewBox="0 0 120 120"`。絵は枠の8〜112に収める。
- 線は`--foreground`、太さ2.5、端と角は丸める。細部の線は1.8。棒状の物(鍵の軸、取っ手)だけ4か5.5。
- 塗りは紙(`--card`)、主色(`--primary`)、差し色(`--brand-accent`)、差し色の淡色(差し色28% + 紙)、墨(`--foreground`)の5つだけ。色の値を直接書かない。
- 主色の面は1つの絵に1〜2か所、差し色は小さな面に使う。グラデーション、影、透過は使わない。
- 文字と数字は入れない(テーマの書体と言語に依存させない)。
- 描くのは物(建物、道具、お金)。人物は描かない。
- 76pxで何の絵か分かる細かさにする。細部は線3〜4本まで、1点は25要素まで。
- 使う要素は`path` / `rect` / `circle` / `ellipse`だけ。`style`、透過、`transform`は使わない。
- 名前は英語のkebab-caseで、場面ではなく物の名前にする(`coffee-machine`。ほかの単元でも使えるように)。

絵柄をそろえる仕組み。

- 手順: `.claude/skills/spot-illustration/SKILL.md`。読む物、形の作り方、確かめ方、描き直しの基準を書いてある。Claude Codeでは`/spot-illustration <単元ID>`で呼ぶ。人が描くときも同じ手順に従う。
- 手本: `spot-illustration.tsx`にある既存の絵。新しい絵は座標の取り方と塗りの配分をここから写す。
- 検査: `spot-illustration.test.tsx`が、要素、色のクラス、線の太さ、要素の数を全部の絵について確かめる(`make test`)。
- 見本: `/illustrations`に全部の絵が並ぶ。`make illustrations`が4テーマ × ライト・ダークの8枚を`logs/illustrations/`に撮る。新しい絵は既存の絵と並べて目で確かめる。

置き方。

- 置くのは場面が変わるステップだけ。同じ単元で同じ絵を2回使わない。ふりかえりや、図解が主役のステップには置かない。
- 図解の「1ステップに1つ」とは別に数える。
- 絵は装飾なので`aria-hidden`。絵でしか伝わらない情報を持たせない。

## 7. 運用

- 置き場所: 図解はコード(`src/components/figures/`)とコンテンツ(```figure)。スポットイラストはコード(`src/components/illustrations/`)とコンテンツ(```illustration)。画像ファイルは置かない。
- 台帳: `docs/assets-ledger.md`に、ファイル名 / 出所URL / ライセンス / 取得日 / 使用箇所を1行ずつ記録する。外部素材(フォント、アイコン)を足すときは必ず同時に書く。自作のイラストは台帳に書かない。
- アクセシビリティ: 図解ブロックは`alt`必須(ビルドで検査)。図の中の文字は12px以上。装飾のイラストは`aria-hidden`。
- テーマとダークモード: 図解もイラストもCSS変数で配色を切り替える。
- 命名と粒度: 1図1メッセージ。1ステップに図は1つまで。ステップの短い説明を超える図解は置かない。
- 見直し: 回答ログで初回正答率が低いステップに図解を追加する(roadmap方針6)。
