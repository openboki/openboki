# 0004. 図解とイラストはコードで描き、画像生成AIの出力は学習コンテンツに使わない

日付: 2026-11-07
状態: 採用(詳細は`docs/visual-guidelines.md`。2026-11-19改定: スポットイラストをunDrawから自作のSVGに替え、「AI生成画像」の範囲を画像生成AIの出力に限る)

## 背景
会計の概念を直感的に理解できる学習体験のため、図解・イラスト・アニメーションを積極的に使いたい。一方で、洗練された統一感、ライセンス(商用・将来の有料化)、拡張性を両立する必要がある。候補として「いらすとや」の活用が挙がった。

2026-11-19の改定の背景: スポットイラストを入れる前に素材を見直した。分かったことは次のとおり。
- unDrawは人物中心の大きな構図で、ステップ見出しの横の小さな枠(76px前後)では潰れる。日本の小さなカフェや軽バンの絵も無い。
- unDrawの色はSVGに焼き込まれていて、4テーマ × ライト・ダーク(ADR 0008)に追従させるには1点ずつ加工が要る。
- unDrawは素材集としての再配布を禁じている。リポジトリごとフォークされるオープンソース(ADR 0007)で、同梱してよいかを確かめられていない。
- 「5つの要素と仕訳」の場面6点をコードで書いたSVGで試作したところ、線と4色だけで統一した絵柄になり、色はテーマのトークンで切り替わった。ユーザーがこの絵柄で統一すると決めた(2026-11-19)。

## 決定
- 会計の構造・流れ・期間の図解は、React + SVGの図解コンポーネントで描き、コンテンツからはYAMLの`figure`ブロックで指定する。5要素の配色と記号(ide-design.md 8章)と自動で一致させる。
- 物語の場面のスポットイラストは、自作のSVGをコードで描く。絵柄は1つに統一し(`docs/visual-guidelines.md` 6章)、色はテーマのトークンだけを使う。コンテンツからは```illustrationブロックで名前を指定する。外部のイラスト素材は使わない。
- いらすとやは主要素材に使わない。理由: 無料枠が「1制作物(または無料公開の1記事)につき20点」で、将来サブスクリプションを導入すると全体で20点の上限に戻る可能性が高いこと、誰もが知るスタイルがサービスの独自性と洗練を損なうこと。
- 画像生成AIの出力(ラスター画像)は学習コンテンツに使わない(一貫性、正確さ、権利の扱い、テーマに追従できないこと)。SVGはコードとして書く。書き手が人でもAIエージェントでも、絵柄の仕様に合わせ、差分のレビューと画面での確認を通す。
- アニメーションはCSSを基本に、M1で`motion`を導入する。Lottie / Riveは使わない。
- 人物やキャラクターを含む独自のイラストスタイルは、必要になってから検討する。それまでは物(建物、道具、お金)の絵だけで成立させる。

## 影響
- M1に図解ブロック(`elements` / `flow` / `timeline` / `taccount` / `proportion` / `compare`)の実装が入る。
- コンテンツ検査に`figure`ブロックのスキーマと`alt`必須を追加する。
- 2026-11-19の改定で、```illustrationブロックと`src/components/illustrations/`を追加する。まず「5つの要素と仕訳」の6ステップで試し、画面で確かめてからほかの単元に広げる。`CLAUDE.md`、`CONTRIBUTING.md`、`docs/vision.md`、ADR 0007の「unDrawのみ」「AI生成画像」の記述をこの改定に合わせる。
