# スマホで学ぶ学習者

**画面**: `mobile: true`(iPhone 13、390×844、タッチ)。途中で`page.setViewportSize`を使って1024pxの境界をまたぐ。

**性格**: 通勤中に片手で使う。ペインをタブで切り替えながら進める。画面が狭いので長い表やポップオーバーがはみ出すと困る。

**狙い**: レスポンシブ。ヘッダーとトップの折り返し、ペインの切り替え、横はみ出し、ポップオーバーとダイアログの位置、
フライングアニメーションの崩れ、タッチでの操作、1024px境界のresize。

**癖**:

1. トップを390pxで開く。ヘッダー(Open簿記 / 3級合格パス / 用語集 / テーマ)が1行に収まるか、「続きから: 〜」のボタンが長い単元名ではみ出さないか。フッターのリンクが押せる大きさか。
2. 単元を開き、タブ「ペインの切り替え」でガイド → ワークスペース → 結果を往復する。各ペインで`check()`(横スクロール)。仕訳エディタに3行ずつ入れたときの折り返しと、「行を削除」が押せる大きさか。スクリーンショットで確認する。
3. 記帳の直後に結果タブへ切り替える。フライングアニメーションが隠れたペインに向かって飛ばないか、数値が更新されるか。
4. 結果ペインの貸借対照表と「会社のかたち」のバーが390pxで読めるか(数値が切れない、ラベルが重ならない)。歴史の単元(`view: ledger`)では試算の表と元帳(T勘定)が横にはみ出さないか。
5. 用語ポップオーバーを画面の端(右端の用語・最下部の用語)で開く。画面内に収まるか。閉じられるか。科目の候補(listbox)が画面の下で切れないか。
6. チュートリアルのツアーを390pxで開始し、スポットライトとカードが対象を隠さないか。「使い方」の「場所を示す」で、対象のあるペインへタブが切り替わるか。
7. 「使い方」ダイアログを開き、分類を開いてスクロールし、閉じる。背景がスクロールしないか。見出し横の「?」と「テーマ」のポップオーバーが画面内に収まるか。
8. 1023px → 1024px → 1023pxとresizeする。ペインの表示が切り替わり、選んでいたタブが保たれるか、入力中の仕訳が消えないか。
9. 横向き(844×390)で仕訳エディタを操作する。「記帳する」が画面内にあり、下の固定バーと重ならないか。
10. classifyステップでタッチ操作(長押ししてドラッグ、押してから箱を押す)の両方を試す。用語集`/glossary`で「用語を検索」に1文字入れ、結果一覧が390pxで崩れないか。

**やらないこと**: 複数タブ、DBの直接確認、テーマごとの配色の検証(theme-switcherが担当)。
