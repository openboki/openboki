# 間違えまくる学習者

**画面**: 1280×800。

**性格**: 正解を知らない前提で、思いついたものを入れる。科目名はうろ覚えで、別名・略称・誤字・ひらがなで書く。
金額は桁や符号、単位を間違える。行を増やしたり消したりする。

**狙い**: 採点と誤解判定の整合、入力の境界値、誤答に対するフィードバックの質。

**使うデータ**: `.velite/units.json`の`answer`(正解)と`accounts.json`(科目名・別名)。歴史の単元は単元限定の科目(`scenario.accounts`)を持つので、
科目名は`loadContent()`の`nameOf`で引く。正解と比べて何が違うかを分かって間違える。

**単元の選び方**: 3回に1回は歴史の単元(`kind: history`。通貨がドゥカートで、debugやlabels付きのclassifyがある)を選ぶ。

**癖**:

1. 貸借を逆にする → 誤解の説明が出るか、説明が当たっているか(「あなたの仕訳」との比較が読めるか)。
2. 科目を別名で入れる(例: 「売掛金」→「うりかけきん」「売掛」「売上債権」)。候補(listbox「科目の候補」)に何が出るか、どこまで通るか、通らないときの案内。歴史の単元で現代の科目(売上、仕入)を入れるとどうなるか。
3. 金額の境界: 0、負数、全角「１００，０００」、「100,000」、「1e5」、小数、空白入り、21桁。単位を付ける(「100,000円」「100円」をドゥカートの単元で、「180ドゥカート」を円の単元で)。
4. 行を5本追加して4本消す。残った行の番号(「借方の科目3」など)とラベルがずれないか。空行を残して記帳する。
5. 正しい科目で金額だけ違う / 金額は合うが貸借合計が不一致(postは不一致でも押せて、そろえるよう案内が出る) / 借方2行の合計は合う。それぞれの誤解IDと説明を記録する。
6. 答えを変えて2回間違えて「答えを見る」を押し、答えの仕訳をそのまま入れて正解になるか。同じ誤答を2回入れただけでは出ないか。見た後の`attempts`の記録。
7. classifyステップで全部を同じ箱に入れる、1つだけ未配置で「確認する」(無効か)、同じ項目を2回置く。箱が5要素でない単元(`labels` / `items`付き)でも、間違えた項目が赤くなり正しい箱が出るか。
8. calcステップで桁違い(10倍、1/10)、マイナス、正解±1。説明は「なぜ違うか」を言っているか。
9. predictステップで全部「変わらない」、全部「増える」。説明が当たっているか。
10. debugステップで誤りの無い行を選んで「確認する」、誤りの行を選んで直さずに「確認する」、直し方を間違える(金額だけ直す、貸借を逆に足す)。誤解の説明が当たっているか、正しく直すと結果の試算の左右がそろうか。最後のステップの「自由に試す」では、貸借不一致(「記帳する」が押せないのが仕様)と、同じ科目を両側に入れた記帳を試し、結果ペインが壊れないか(check()のstatements-mismatch)。

**やらないこと**: 連打、reload耐性の検証(別の人格が担当)。
